Opt in to capturing uncaught JVM exceptions on the server SDK via `PostHogConfig.captureUncaughtExceptions` (also on the config `Builder`). When enabled, `PostHog` installs a global `Thread.defaultUncaughtExceptionHandler` on setup that captures the crashing exception as a fatal, unhandled `$exception` event (mechanism `UncaughtExceptionHandler`), flushes, and then delegates to the previously registered handler; the handler is removed again on `close()`. Unlike the Android SDK this is gated purely on the local flag — the server SDK never fetches remote config. The crash capture is enqueued asynchronously like any other event, and the crash path then performs a bounded blocking flush that is ordered behind that pending enqueue and ignores `flushAt`, so the event gets a network attempt before the JVM exits without ever blocking the crashing thread indefinitely. Delivery stays best-effort, the same guarantee class as the Android SDK: the flush can hit its timeout, the HTTP attempt can fail, and an immediate hard exit can cut it short. Sending the fatal event itself synchronously and independently of the queue threshold is a known follow-up.
